> 毕业设计（论文）系统设计方案
>
> 题目：基于微信小程序的英语口语 AI 陪练系统设计与实现

---

## 一、系统总体架构设计

### 1.1 架构概述

系统采用**前后端分离 + 微服务化**的三层架构，整体分为：

- **表现层（微信小程序端）**：负责用户交互、语音采集与播放、界面渲染。
- **业务层（后端服务）**：负责模型调度、对话管理、场景配置、反馈评估、用户与数据管理。
- **基础设施层**：数据库、缓存、对象存储、第三方 AI/语音服务。

### 2.2 核心模块详细设计

#### 2.2.1 场景中心

- **场景分类**：日常生活、校园学习、职场办公、旅行出行、面试求职、自由话题。
- **场景配置**：每个场景包含 `场景ID、名称、描述、角色设定（AI 扮演的角色）、背景设定、难度等级、推荐英语水平、关联 Prompt 模板`。
- **示例场景**：

| 场景 | AI 角色 | 对话目标 |
|------|---------|----------|
| 餐厅点餐 | 服务员 | 练习点餐、询问菜品、结账 |
| 机场值机 | 值机柜台工作人员 | 办理登机、行李托运 |
| 求职面试 | HR 面试官 | 自我介绍、回答问题 |
| 酒店入住 | 前台接待 | 办理入住、询问服务 |
| 校园选课 | 学长/学姐 | 咨询课程、交流学习 |

#### 2.2.2 对话陪练（核心）

**对话流程**：

```
用户进入场景 → 选择模型 → 开始对话
    ↓
用户语音输入 → ASR 转文字 → 发送后端
    ↓
后端拼接 Prompt（系统设定 + 场景设定 + 历史对话 + 用户输入）
    ↓
调用大模型 → 流式返回 AI 回复
    ↓
TTS 将回复转语音 → 小程序播放
    ↓
同时返回文字反馈（语法纠正/建议）
    ↓
循环 ←→
结束对话 → 生成总结评分
```

**多模型调度设计**：

设计统一的 `ModelAdapter` 接口：

```typescript
interface ModelAdapter {
  name: string;                    // 模型标识
  chat(messages: Message[], options?: ChatOptions): Promise<ChatResponse>;
  streamChat(messages: Message[], options?: ChatOptions): AsyncIterable<string>;
}
```

各模型实现该接口（QwenAdapter、DeepSeekAdapter、ErnieAdapter），通过 `ModelFactory` 按用户选择实例化，便于扩展。

#### 2.2.3 实时反馈

在 AI 回复的同时，对用户的上一轮输入进行分析：

- **语法纠正**：标记语法错误并给出正确表达；
- **词汇建议**：推荐更地道的词汇/短语；
- **发音评分**：基于 ASR 置信度给出发音评分（0-100）；
- **流利度评估**：基于语速、停顿次数评估。

反馈以"小卡片"形式附在对话消息下方。

#### 2.2.4 学习记录

- 每次对话保存完整记录（时间、场景、模型、消息列表、评分）；
- 提供按时间/场景筛选的历史回看；
- 统计学习时长、对话次数、平均评分，绘制能力曲线。

## 三、场景与 Prompt 设计

### 3.1 Prompt 结构设计

采用 **System Prompt + 场景设定 + 对话历史** 的拼接方式：

```
[System]
You are an English speaking practice partner. You will play a specific role in a given scenario.
Rules:
1. Speak in English at a level appropriate for the learner.
2. Keep responses concise (1-3 sentences) to simulate real conversation.
3. After the learner speaks, provide brief feedback on grammar/vocabulary in a separate <feedback> block.
4. Stay in character at all times.

[Scenario]
Role: Waiter at a restaurant
Scenario: The customer is ordering dinner
Difficulty: Intermediate (B1)

[History]
... (最近 N 轮对话)

[User]
I want a burger and a cola.

<feedback>
- Grammar: ✓ correct
- Vocabulary suggestion: "I'd like a burger and a cola" sounds more natural and polite.
- Pronunciation: 85/100
</feedback>
```

## 五、接口设计（核心）

|------|------|------|
| POST | /api/auth/login | 微信登录 |

### 5.2 WebSocket 对话接口

- 连接：`wss://your-domain.com/ws/chat/:sessionId`
- 客户端发送：`{ type: 'text'|'audio', content: '...' }`
- 服务端流式推送：`{ type: 'chunk'|'feedback'|'audio'|'done', ... }`

## 六、关键技术实现要点

### 6.1 多模型适配层

```
ModelFactory
  ├── QwenAdapter      → dashscope.aliyuncs.com
  ├── DeepSeekAdapter  → api.deepseek.com
  ├── ErnieAdapter     → aip.baidubce.com
  └── (可扩展)
```

统一封装为 OpenAI 兼容调用，新增模型只需实现 `ModelAdapter` 接口。

### 6.2 语音交互链路

- **录音**：小程序 `wx.getRecorderManager()` 录制 mp3；
- **识别**：上传至后端调用 ASR，或使用微信同声传译插件在前端识别；
- **合成**：后端调用 TTS 返回音频 URL，小程序 `wx.createInnerAudioContext()` 播放。

### 6.3 对话上下文管理

- 采用滑动窗口策略，保留最近 N 轮对话（如 10 轮）作为上下文；
- 会话上下文缓存于 Redis，key 为 `session:{sessionId}:context`，TTL 30 分钟。

### 6.4 反馈生成

在大模型调用中，通过 Prompt 要求 AI 在回复后追加 `<feedback>` 标签，后端解析该标签并结构化存储。

## 七、安全与性能考虑

1. **鉴权**：所有接口需携带小程序登录态 token；
2. **限流**：按用户/IP 限流，防止滥用；
3. **成本控制**：限制单次会话最大轮次、模型调用频率；
4. **隐私**：对话内容存储需脱敏，用户可删除历史。

---

## 八、测试方案

1. **单元测试**：模型适配层、反馈解析、评分逻辑；
2. **接口测试**：Postman / Swagger 测试全部 REST 接口；
3. **前端测试**：真机调试（开发者工具 + 真机预览）；
4. **性能测试**：JMeter 压测对话接口，验证并发能力；
5. **用户测试**：邀请 10-20 名志愿者试用，收集反馈并评估口语提升效果。
